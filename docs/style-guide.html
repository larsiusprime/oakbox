1. Buttons

An action is a raised button: it rises, and sinks when pressed. Going somewhere is a link. Unfolding something in place is a chevron. Choosing from a list is a dropdown, a segmented control or a row.

Button

Any ordinary action. "…" means it opens a dialog first.

Primary

The one action a step or dialog is for. One per view.

Danger

Deletes for good: a trash can with its words, and it always asks first.

Add

The one way to add. After the list it adds to, or inside an item when it adds to that item.

Small button new

✓ 83% match parcels

An action beside a line of text: after a check, inside a row. Same bevel, 80% size.

Tool button new

An icon action. A toggle stays pressed in while it's on (try the map). Its label is read aloud and shown on hover.

Close button new

closes a popup, hides a panel

A grey ✕, only at the top right of a popup, panel or dialog. Nothing is lost. A row not saved yet is taken away with the red −, like any item.

Remove new look

Takes something off a list or a step; it can be undone. A red −, the pair of Add's +, last on its line at the right edge. With words, it's the same red button: its white −, then the words.

2. Files and items

A file sits in one thin outline as wide as what's in it. Its first line is a faint band: its name in OAK box, its file name set off like code.csv, its facts, actions, then the red −. What's set on the file is inside. Anything removable on its own has its own box.

4. The rules

  1. An action is a raised button. Ordinary, primary (one per view), danger (can't be undone), add, small (beside a line of text), tool (an icon; a toggle stays pressed in), close (grey), remove (red).
  2. Going somewhere is a link; one that leaves the app carries ↗. Unfolding in place is a chevron. Choosing from a list is a dropdown, a segmented control (two or three options), radio cards (options that need a line each) or a selectable row.
  3. Flat is a choice. Every flat control is in section 3 with its reason; a new one is added there, or made a button.
  4. Close and remove never share a look: close is a grey ✕, only at the top right of a popup, panel or dialog; remove is a red −, at the end of the item it removes. Each shows what it does on hover, and its label is read aloud.
  5. A remove can be undone: "Removed parks · Undo" shows for a few seconds after it.
  6. Every button that takes something away says so with its symbol: a − when it removes from a list or a step (it can be undone), a trash can when it deletes for good (a danger button, with its words, and it asks first). Never words alone, and never a trash can for something that can be undone.
  7. A file is one entry (FileEntry): a thin outline as wide as what's in it, its first line a faint band (name, file.csv, facts, actions, −), its settings inside on two columns, on a body tinted a third of the way from white to that band (its rows stay white). Entries in one list share one width, with their Add button at its right edge.
  8. Boxes inside the same file stack flush: no space between them, one border line where they meet.
  9. Anything removable on its own has its own box and its − at the right; its siblings get one too. A table's rows are boxed already by its lines: a removable row ends in its −. Adding to an item is inside it; adding another item is after the list.
  10. Settings line up on two columns, labels then what's set, in a file's body and outside one. Not a sentence with a blank in it ("A sale demolished within [365] days…"), which stays a sentence, nor a question with its answers below it.
  11. A file's name is set off wherever it appears: like code.csv in a sentence, a dialog's title or a dropdown, and a name in OAK box in mono.
  12. Only tables take the page's width; a map opened in an entry does too. Everything else is as wide as what's in it.
  13. Nothing pressable is only a table row or a chart: a pressable row is a shortcut to a link or button in it, and a chart that opens shows its enlarge icon.
